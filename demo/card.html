ui-card

One item in a grid: an optional eyebrow, a heading, a body and a row of actions. ui-cards lays those out, so a catalogue fills the space it is given — several per row on a desktop, one on a phone — with no media query of your own. Give a card an href and it becomes one real link whose accessible name is the card's own title, rather than a div with a click handler and a separate invisible link somewhere inside it.

Interception

Every card emits ui4u:press. A binding through bind('press', …) runs before the card acts and can veto it — returning false blocks the navigation too, not just the event. This card starts out vetoed so it cannot navigate away from the demo by accident; the button switches the veto off.

The grid

Six cards in one ui-cards. It decides nothing but the track count: by default it auto-fills from a minimum width, so the count is whatever the space allows. Set columns and the count is fixed instead — and forced back to one below a phone width, because two cards side by side on a small screen is a hit area nobody can hit.

Panels, keyboard navigation and a real roving tab stop. Modal and non-modal, portalled to the body, focus trapped. A real native control with hint, error and validity. Sorting, search, selection and copy. Positioning that survives a transformed ancestor. A collapsible rail that remembers its state.

Markup, API and the tokens the surface is built from. All three blocks are copyable.
  • A card with href is a real <a> around its own heading, so its accessible name is the card's title and middle-click, “open in new tab” and the status bar all keep working. There is no second, invisible link hiding inside it.
  • The card is one tab stop. A card that has actions adds them as the next stop, so Tab reaches the link and then the buttons, in that order.
  • The grid is role="list" and every card is role="listitem", applied on each change — so a card added later is still announced as an item rather than as an orphan. label names the list; an unlabelled one is announced as an unnamed group.
  • A card is a container, not a tab stop of its own: it carries tabindex="-1" so the arrow keys can move focus into it, and never 0. Tab therefore lands on the card's own link or first control.
  • ArrowRight and ArrowLeft move between cards and land on the next card's link or first control. Movement clamps at the ends rather than wrapping.
  • Only an interactive card lifts on hover. A static card that raised itself would promise something it does not do.
