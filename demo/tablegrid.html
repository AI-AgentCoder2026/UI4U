The author writes a plain <table>. The component keeps it and adds column groups, sorting, search, pagination and keyboard navigation.

  • Each sortable header contains a real <button>, so sorting works from the keyboard without re-implementing button semantics.
  • aria-sort is applied to exactly one header at a time, using ascending / descending / none.
  • A column marked data-type="number" compares numerically, and a formatted cell can carry data-value for the real number.
  • Group headers keep their native scope="colgroup" / scope="col" semantics, so a screen reader announces which group a column belongs to.
  • Search and paging hide rows rather than deleting them, so the arrow keys skip rows that are not on screen instead of landing on an invisible cell.
  • The pager status is a role="status" live region, so a page change is announced without moving focus.
  • navigate is opt-in. A plain <table> is already navigable by a screen reader; grid roles and a roving tab stop are only added when you ask for cell-by-cell keyboard movement.
